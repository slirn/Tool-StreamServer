# M3 · 推流鉴权与流生命周期事件 · Plan

- 状态：**已批准**（2026-08-27，用户"全部按推荐"）
- 分支：feature/m3-auth

## 1. 目标

推流必须持有效签名（HMAC + 过期），拒绝无签名/过期/篡改的推流；补全 subscribe/unsubscribe 拉流事件；为 M4 踢流做好会话管理。

## 2. 已批准决策

1. 推流鉴权：HMAC 签名带过期（`?expire=<unix>&sign=<hmac(secret, path+expire)>`）
2. 拉流：v1 开放不鉴权
3. 推/拉共用 AUTH_SECRET
4. 宽限期可配置 → **执行中核实**：NMS 的 30s 宽限是其源码常量，不可配置；若无法干净暴露则记偏差跳过
5. HTTP-FLV 已随 M2 获得，M3 实际范围 = 鉴权 + 流事件 + 会话管理

## 3. 方案

```
src/auth/signature.ts    纯函数：sign(path, expire, secret) / verify(...)（可单测）
src/auth/policy.ts       AuthPolicy 实现（M1 接口落地）
ingress/nms-server.ts    鉴权接线（机制依 NMS 源码调研结果：prePublish 事件或
                         postPublish 时校验并关闭会话）+ sessions 表 + kicked 处理
core                     subscribe/unsubscribe 事件补全（postPlay/donePlay → bus）
```

## 4. 测试计划

- 单元：签名生成/校验（过期、篡改、时钟容差）、policy 拒绝路径
- e2e 扩展：合法签名推流成功出片；**错误签名推流被拒**（registry 无此流、推流端被断开）

## 5. 风险

- NMS v4 拒绝推流的机制未定（源码调研后定，偏差记录）
- HMAC 算法选择固定 sha256；时钟容差 ±60s

# DSH 协作流程规范

本文档把"如何与 DSH（DeepSeek Harness）协作"固化为团队纪律，是所有 agent 任务的默认上下文；人类协作者也应以此为标准派活与验收。

## 1. 工作模型（三条纪律）

1. **工作区即项目**：每次会话在项目根目录启动，agent 始终以本项目为上下文，禁止在无关目录操作。
2. **先读再写**：agent 动手前必须读取 README / ARCHITECTURE / CONTRIBUTING；规范文档即默认输入，先把约定写下来，再让约定约束行为。
3. **用工具约束流程**：plan / todo / goal / subagent / workflow / 后台任务 是流程标准化的抓手，不是摆设。

## 2. 任务流转（标准姿势）

```
分配任务 → 读规范 → Plan 模式出方案 → 人工确认 → todo 分解
→ 实现（可并行子代理）→ 测试 → 审查（子代理按清单）→ DoD 勾选 → 变更清单
```

## 3. 场景速查

| 场景 | 推荐姿势 |
| --- | --- |
| 新功能开发 | plan 方案与改动清单 → 确认 → todo 分解 → 实现 + 测试 → 并行 review → 回归 |
| Bug 修复 | 复现并定位根因（grep + 最小复现）→ 先写失败测试 → 修复 → 全量测试 |
| 重构 / 迁移 | grep 摸清全部引用面 → 迁移计划 → workflow 分批执行 → 每批验证 |
| 代码审查 | 子代理按 CONTRIBUTING §7 清单逐项审，输出（级别 + 位置 + 建议） |
| 写文档 / 方案 | 子代理调研 → 给框架 → agent 成稿 → 另一子代理做事实核查 |
| 长周期目标 | 用 goal 登记，跨会话持续推进，断线恢复可续 |

## 4. 效率工具的使用边界

- **并行子代理**：互不依赖的任务同时开 2~4 个；规格先行天然形成 TDD 分工
- **Workflow**：跨大量文件 / 条目的 fan-out（全量审计、批量迁移、逐文件规范检查）
- **后台任务**：build / test / 打包等长命令后台跑，完成有通知，不空等
- **Goal**：半天以上的目标持久化，跨轮次持续推进
- **工具优先**：定位代码用 grep / glob，查最新 API 用 web_search，不凭记忆猜

## 5. 安全与权限纪律

- 文件操作默认限定在 workspace（workspace-write 模式），越界写会触发审批；保持默认，仅在确实需要时临时授权
- 权限最小化：不让 agent 以危险权限跑日常任务
- 敏感信息（密钥 / token）不进代码、不进日志、不进提交

## 6. 任务收尾模板（DoD 报告）

```
变更文件清单：
- <路径>：<改动摘要>
- ...
验证结果：
- [x] npm run lint
- [x] npm test
- [x] npm run build
- [x] 文档同步
遗留问题：<无 或 列出>
```

# team-code-review：代码审查清单

**MANDATORY** —— 审查 StreamServer 的代码 / PR 时，逐项过以下清单，输出结构化结果。

## 审查维度（逐项确认，不得跳过）

### 1. 安全性
- [ ] 鉴权不可绕过（推流/拉流/管理 API 各路径都过 `auth`）
- [ ] 日志不泄露密钥 / token / 签名参数（`AUTH_SECRET` 等）
- [ ] 外部输入（streamKey、URL 参数、请求体）均有校验与长度限制
- [ ] 无路径穿越 / 命令注入风险（尤其涉及文件路径、ffmpeg 参数拼接处）

### 2. 边界条件
- [ ] 空值 / undefined / 空数组路径
- [ ] 同一 streamKey 重复推流的竞争行为
- [ ] 订阅者先于发布者到达、发布者断开时订阅者的表现
- [ ] 超长运行 / 大流量下的资源上限（分片数、连接数）

### 3. 错误处理
- [ ] 异常路径有日志且可恢复；不吞错（空 catch）
- [ ] 网络错误 / 客户端断开不会导致进程崩溃或句柄泄漏
- [ ] 错误码与 HTTP 状态符合 team-api-design 规范（如适用）

### 4. 性能
- [ ] 热点路径（每帧 / 每包回调）无同步阻塞、无重复计算
- [ ] 无内存泄漏：监听器、定时器、分片文件在流结束后清理
- [ ] 大对象无多余拷贝（Buffer 传递尽量零拷贝）

### 5. 测试覆盖
- [ ] 新逻辑有对应单元 / 集成测试；上述 1~4 中每个修复点有用例
- [ ] Bug 修复附带了"先失败后通过"的复现测试

### 6. 架构与规范
- [ ] 依赖方向符合 ARCHITECTURE §4（`core` 不依赖传输层；`ingress`/`egress` 互不引用）
- [ ] 无 `any`（豁免需注释）；类型导入用 `import type`
- [ ] 提交信息符合 team-commit；README/ARCHITECTURE 已同步

## 输出格式（结构化问题列表）

```
# Review 报告
结论：通过 / 有条件通过 / 拒绝

| # | 严重级别 | 位置（文件:行） | 问题 | 建议 |
|---|---------|----------------|------|------|
| 1 | blocker  | src/egress/hls.ts:88 | …   | …    |

级别定义：blocker（必须改）/ major（应改）/ minor（建议）/ nit（可忽略）
清单覆盖：安全性✓ 边界✓ 错误处理✓ 性能✓ 测试✓ 架构✓
```

## 纪律

- 只对 diff 审查，但要看 diff 在模块中的上下文
- 按模块可拆给多个并行子代理，最后合并为一份报告
- blocker 未解决不得合入
